# WaveRPC v0.3.0-alpha.0 Release Notes

**Release Date**: August 26, 2026  
**Release Stage**: Alpha (`v0.3.0-alpha.0`)

WaveRPC `v0.3.0-alpha.0` is the first usable alpha milestone release for the WaveRPC platform. It establishes a fully functional, local-only bridge connecting web music streaming with Discord Rich Presence.

---

## 📦 What's Included

This alpha release delivers the baseline end-to-end integration across the monorepo architecture:

- **Chrome Extension (Manifest V3)**: Content script for streaming service monitoring and background service worker bridging.
- **Desktop Runtime Service**: Background process managing local WebSocket connections, provider state, and native Discord IPC pipe interactions.
- **Shared Package Core (`@waverpc/shared`)**: Unified track schemas, presence models, strongly typed event emitter, and privacy sanitization pipeline.
- **Provider Architecture (`@waverpc/providers`)**: Extensible provider interface (`BaseProvider`), provider registry, and SoundCloud playback detection module.

---

## 🟠 Current SoundCloud Support

SoundCloud is the initial target music streaming provider supported in `v0.3.0-alpha.0`:

- **Real-Time Playback Extraction**: Captures track title, artist name, track URL, artwork URL, duration, current timestamp, and playing/paused state.
- **Rich Presence Card**: Displays active track metadata, album artwork, dynamic elapsed/remaining timestamps, and provider branding on your Discord profile.
- **Playback Controls & State**: Updates status instantly on play, pause, seek, or track switch, and emits `TRACK_CLEAR` when playback stops or tab is closed.

---

## 🔒 Privacy Architecture

WaveRPC is engineered with a strict **local-only, privacy-first** paradigm:

- **Zero Remote Dependencies**: No external server infrastructure, third-party backend API calls, or remote telemetry.
- **Local WebSocket Bridge**: Communication between extension and desktop occurs over `ws://127.0.0.1:41920`.
- **Direct Local IPC**: Desktop service communicates with Discord Desktop via OS local named pipes (`\\.\pipe\discord-ipc-0` through `9` on Windows).
- **PrivacySanitizer**: Built-in sanitization redacts sensitive authentication parameters, session tokens, and tracking query params before broadcasting presence data.

---

## ⚡ Reliability & Stability Improvements

- **Discord IPC Pipe Scanning**: Sequential scanning across native IPC pipe paths (`0-9`) to ensure reliable connection with Discord Desktop.
- **Automatic Reconnect & Exponential Backoff**: Capped backoff strategy for WebSocket client reconnects and Discord IPC reconnect attempts.
- **Presence Deduplication**: State hashing prevents redundant IPC writes and reduces CPU/network load.
- **Automated Testing Suite**: High-coverage test suite verifying privacy rules, payload generation, transport protocols, and reconnect handlers.
- **Windows E2E Verification**: Confirmed operational stability on Windows with active Discord Desktop and SoundCloud web player.

---

## ⚠️ Known Alpha Limitations

Please note the following limitations during the Alpha stage:

1. **Development Build Required**: Packaged desktop installers (`.exe` / `.msi`) and Chrome Web Store extension packages are not yet included in this release. Build from source is required.
2. **Single Supported Provider**: Only SoundCloud is currently implemented and supported. Spotify, YouTube Music, Apple Music, and generic browser media sessions remain as planned roadmap items.
3. **Manual Discord Client ID Setup**: Requires setting `DISCORD_CLIENT_ID` in `.env` or environment variables for local Discord Application authentication.
4. **Discord Desktop Client Required**: Requires the official Discord Desktop application running locally on the same system.

## 🛠️ Installation & Development Notes

### Environment Configuration

WaveRPC requires a valid public Discord Application Client ID. Set this in `.env` in the repository root:

```env
# Public Discord Application Client ID
DISCORD_CLIENT_ID=123456789012345678
```

### Build & Run

```bash
# 1. Install workspace dependencies
pnpm install

# 2. Build TypeScript packages & applications
pnpm run build

# 3. Run automated tests
pnpm test

# 4. Start Desktop application
pnpm --filter @waverpc/desktop start
```

### Loading Extension in Chrome

1. Open `chrome://extensions` in Google Chrome.
2. Enable **Developer mode** in the top-right header.
3. Click **Load unpacked** and select the `apps/extension` directory.
